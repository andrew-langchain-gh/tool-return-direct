Skipping the ReAct review call for A2UI tools

You can drop the redundant LLM call after an A2UI tool and still keep the data referenceable in later turns. But the obvious way to do it doesn't work — and fails quietly.

Verified 10 Aug 2026 langchain 1.3.14 langgraph 1.2.10 model claude-sonnet-4-6

The short version

What to change

Keep

return_direct=True on the A2UI tool. The tool may return a Command — but its messages update must contain only the ToolMessage.

Move

The hand-built AIMessage out of the tool and into an after_agent middleware hook.

Result

One model call per surface-rendering turn instead of two, and the thread still contains a proper AIMessage that later turns can reason over.

The rest of this page explains why the placement matters. If you only take one thing: putting the AIMessage inside the tool cancels return_direct outright.

Mechanism

How the short-circuit actually decides

When the tools node finishes, a conditional edge decides whether to end the turn or go back to the model. It makes that call by scanning backwards through the message list for the most recent AIMessage, then checking whether every tool that message called is marked return_direct. 

# langchain/agents/factory.py — _make_tools_to_model_edge
last_ai_message, tool_messages = _fetch_last_ai_and_tool_messages(state["messages"])

client_side_tool_calls = [
    c for c in last_ai_message.tool_calls if c["name"] in tool_node.tools_by_name
]
if client_side_tool_calls and all(
    tool_node.tools_by_name[c["name"]].return_direct for c in client_side_tool_calls
):
    return end_destination      # short-circuit: turn ends here
...
return model_destination        # the slow, redundant call

Two things follow. The decision reads the message list as the tool left it — so anything the tool wrote is already visible. And it looks at nothing else: not the Command, not the ToolMessage content.

Placement

Why the same code works or fails on one line's position

Both routes below produce identical thread history. The only difference is when the AIMessage is added — and that changes which message the backwards scan lands on.

Synthetic message has no tool_calls → the return_direct branch is skipped → edge falls through to the model. 2 model calls. On Anthropic the second one is a hard 400, because history now ends on an assistant turn.

Scan finds the real tool-calling message, all its tools are return_direct → turn ends. 1 model call. The middleware then appends the synthetic message outside the loop, so routing never sees it.

Reordering the two messages inside the tool does not help. Putting the AIMessage first fails the same check and produces an invalid tool-call / tool-result sequence.

Implementation

The working pattern

The tool — ToolMessage only

@tool(return_direct=True)
def fetch_account_summary(account_id: str, runtime: ToolRuntime) -> Command:
    """Fetch an account summary and render it as an A2UI surface."""
    data = load_account_summary(account_id)
    surface = build_a2ui_surface(data)

    # Push to the UI immediately — your existing queue flush goes here.
    get_stream_writer()({"type": "a2ui_surface", "surface": surface})

    return Command(
        update={
            "a2ui_surfaces": [surface],
            "messages": [
                ToolMessage(
                    content=render_summary(surface),
                    tool_call_id=runtime.tool_call_id,
                )
            ],                          # ← no AIMessage here
        }
    )

The middleware — deterministic, no model call

@after_agent(state_schema=A2UIState)
def append_a2ui_summary(state: A2UIState, runtime: Runtime) -> dict[str, Any] | None:
    """Restate a return-direct A2UI result as an AIMessage."""
    last = state["messages"][-1]
    if not isinstance(last, ToolMessage) or last.name not in A2UI_DIRECT_TOOLS:
        return None                     # ← guard: runs on every turn
    return {"messages": [AIMessage(content=render_summary(state["a2ui_surfaces"][-1]))]}

render_summary is template-driven text built from data the tool already holds. No model is involved, so the message costs nothing.

State and wiring

class A2UIState(AgentState):
    a2ui_surfaces: NotRequired[Annotated[list[dict[str, Any]], operator.add]]

agent = create_agent(
    model="anthropic:claude-sonnet-4-6",
    tools=[fetch_account_summary],
    middleware=[append_a2ui_summary],
    state_schema=A2UIState,
    checkpointer=InMemorySaver(),
)

The reducer on a2ui_surfaces matters because the model can call tools in parallel, and concurrent writes to one field need a merge rule.

Before you ship

Four things that will bite

  • It's all-or-nothing per turn. return_direct short-circuits only if every tool called in that turn has it set. One ordinary tool in a parallel batch sends the whole turn back through the model.
  • after_agent fires on every turn, including normal conversational ones that already ended with a real model response. Without the guard you'll staple synthetic text onto those too.
  • Message order is load-bearing. The synthetic message must carry no tool_calls and must follow the ToolMessage. That sequence is valid input for both Anthropic and OpenAI on the next turn.
  • get_stream_writer() needs a graph context. A tool that calls it can't be invoked standalone in a unit test — inject the writer or guard the call if you want direct-invocation tests.

Open question

One answer could make this simpler

We still need to confirm how "search in later turns" is implemented on your side, because it changes the recommendation:

  • Full thread history replayed to the model — the synthetic AIMessage is the right fix, exactly as above.
  • A separate retrieval or embedding index — point it at ToolMessage content directly. Then you need no fabricated message and no middleware at all: the tool plus return_direct=True is the whole solution.

Worth checking early. The second answer removes code rather than adding it.
